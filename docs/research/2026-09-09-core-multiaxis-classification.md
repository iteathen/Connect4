## Purpose

This file corrects an earlier classification mistake: separate categories must remain separate. No candidate receives one composite score.

The candidates classified here are the previous clear-winner group only:

- RWS — residual win-space as semantic state
- RID — fixed residual-requirement universe / 625-ID substrate
- SUP — minimal exact physical/support state
- FW — fixed-width, allocation-free hot kernel
- INC — precomputed/incremental residual transitions and metadata
- IWIN — exact immediate-win closure
- DTH — exact double-immediate-threat forced-loss closure
- FBLK — forced single-response restriction
- FMAC — forced macro-edges / decision-state exposure
- EWB — cheap exact earliest-win bounds, currently cardinality fallback
- CTT — compact exact TT identity
- PH — proof/bound authority separated from ordering hints
- AUTO — residual automorphism/equivalence collapse
- DEAD — elimination/compression of genuinely dead physical distinctions

### Pairwise compatibility interpretation

The `X?` cells are the places where the current group itself needs deliberate synthesis:

1. **RWS/SUP with FW** — semantic richness must compile to a very small fixed-width state.
2. **SUP with CTT/AUTO/DEAD** — support state participates in exact identity and equivalence; these cannot each canonicalize a different physical model.
3. **FW with CTT/AUTO/DEAD** — all three can add per-node work, so representation-native forms are required.
4. **CTT with AUTO/DEAD** — canonicalization changes the key domain; compact-key encoding must follow the final normalized identity.

No pair in the clear-winner set is currently classified as fundamentally incompatible. Several are **not independently composable in their current prototype forms**, which is a different statement.

## Category 10 — current pairwise substitution/overlap cases

These deserve explicit tracking because treating them as additive features would double-count value or create duplicate state truth.

- **IWIN/DTH/FBLK vs FMAC:** FMAC repeatedly consumes these primitives. Do not count the same forced-state elimination twice.
- **EWB cardinality vs future support-aware earliest-win bound:** likely fallback/subsumption relationship, not necessarily additive.
- **AUTO sibling-orbit pruning vs future full canonicalization:** full canonicalization may subsume the separate orbit mechanism.
- **DEAD global neutral pool vs future support-event canonicalization:** event state may subsume safe neutral/dead distinction handling.
- **CTT current residual-key encoding vs future compact-key encodings:** alternatives, not stackable optimizations.
- **SUP heights vs support-event frontier:** alternative realizations of the same authoritative physical-state responsibility.

## Category 11 — current classification changes caused by keeping axes separate

Keeping categories orthogonal produces several conclusions that a single score would hide:

- **DEAD** can have high expected usefulness and high amplification potential while simultaneously having high form risk and medium-high exclusion risk.
- **CTT** can be very likely as a principle while the current encoding has high implementation-form risk and co-design tension with AUTO/SUP.
- **SUP** is near-certain even though its concrete form is one of the least settled components.
- **FMAC** has very strong evidence and adoption likelihood, yet overlaps substantially with FBLK and tactical closure because it is built from those primitives.
- **FW** is near-certain and performance-qualified, but that does not mean every semantic feature is automatically compatible with it; RWS/SUP/AUTO/DEAD still have a separate performance-integration problem.

## Rule for future classification

Never collapse these axes into one score unless the project owner explicitly requests an aggregate decision function.

For every candidate retain separately:

1. expected usefulness/adoption likelihood;
2. evidence maturity;
3. hot-path performance risk;
4. amplification potential;
5. architectural dependencies;
6. exclusion risk;
7. implementation-form risk;
8. relationship type;
9. pairwise compatibility;
10. substitution/overlap relations.

Later portfolio selection may consume these categories, but must not erase them.
