# Additional validation of shipped IsoMax

These new qualification helpers import the shipped package and leave its production runtime unchanged. The package test directory contains every reusable helper, so offline tarball validation does not depend on a producer checkout.

Run these commands from the repository root using the same Node executable selected for the main qualification. The outcome runner requires `--experimental-ffi` for the shipped Windows affinity and memory discovery APIs.

```powershell
& $node --test isomax/test/tt-stress-review.test.mjs isomax/test/review-validation-physical-reference.test.mjs
& $node --experimental-ffi --max-inlined-bytecode-size=2400 --max-inlined-bytecode-size-cumulative=9600 --import ./isomax/runtime/tools/benchmark-v8-startup-preload.mjs isomax/test/review-validation-outcomes.mjs --mode small --count 240 --output docs/qualification/20261007-review-validation/validation/small-outcomes.json
& $node --experimental-ffi --expose-gc --max-inlined-bytecode-size=2400 --max-inlined-bytecode-size-cumulative=9600 --import ./isomax/runtime/tools/benchmark-v8-startup-preload.mjs isomax/test/review-validation-outcomes.mjs --mode full12 --output docs/qualification/20261007-review-validation/validation/full12-outcomes.json
```

The full-capacity command must run serially. Each of its 16 roots gets a fresh process, six physically pinned workers, a real 12 GiB shared partial24 TT split into two 2^28-entry banks, and compiled support views. Geometry is prepared independently in each child; startup flags are restored explicitly after the worker preload strips process.execArgv. This avoids relying on immediate GC reclamation between allocations. It is outcome/resource validation, not empty-board performance sampling.

The small command checks 240 deterministic legal nonterminal roots distributed across ranks 32 through 39, with small banked shared and private TTs. The full command selects roots across all eight ranks and distinct generated trajectories, plus reflections. `--count` controls small-mode cases; `--cases INPUT.json` supplies an array of `{id,moves}` for late 7x6 roots. Early roots are rejected by this bounded physical-reference runner. `--package PACKAGE_DIRECTORY` runs against an extracted tarball while retaining the same independent reference helper.

The physical oracle uses column arrays and explicit four-direction line checks, legal gravity moves, and recursive minimax with full physical-board memoization. It imports no solver, bitboard, RBA, residual-support, or cache-key implementation. Expected WDL and optimal physical columns are evaluated in the parent only after every solver return. The runner also checks readiness, affinity, compiled views, actual bank payload/boundaries, and six-worker cleanup, and writes partial progress before continuing. A failed case is preserved and the runner collects later independent failures.

The concurrency test starts six writers and two readers behind a shared barrier. Writers contend over single-bank boundary rows and the first/last rows of four small banks. Every row has six writer identities plus a never-published collision identity. A successful probe must return that key's fixed proof tag; misses are allowed during replacement/publication. Tags necessarily repeat because the proof format has only five nonzero tags. Busy rows, sequence wrap, whole-object clones, signed locators, actual shipped worker hash preambles, and 100 geometry TT/reflection guards are covered separately.

Coverage limits: synthetic keys validate the current nonterminal partial-key shape and publication contract, not solved game outcomes. Small banks exercise addressing and races. Full12 establishes actual selected-position allocation/behavior, not exhaustive standard7x6 correctness or full-table replacement behavior. The 100-geometry sweep does no searches, including 10x10. The physical reference is independent qualification code, not an externally certified oracle. The separately audited Pons position adapter checks nine frozen early roots at ranks8..16 and their returned witnesses; see ../comparison/early9/summary.json.

Execution record: the initial bounded launch overlapped timing pair01 and was stopped; that pair is excluded and replaced. The bounded stress/reference suite passed9/9 on Node26.7; a later sign-convention regression also passes. `small-240.json` has240 exact root/WDL/witness checks with zero failures and all three WDLs. `full12-16.json` has16 cold full-capacity cases with zero failures, and `full12-draw.json` adds an actual full-capacity draw control. Every solver result uses player0-relative WDL; the physical reference reports mover-relative WDL and is converted only after return. `harness-corrections.json` explains preserved invalid/incomplete attempts. `full12-default-jit-*` records additional successful capacity checks without the retained process-wide JIT flags; those are not the primary configuration record.
