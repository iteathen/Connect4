## DP-16 — causal / temporal structure

The scheduler event with the strongest exact timing relationship is not “manager chooses worker.” Current source already eliminates that.

The relevant timeline is:

```text
leaf becomes manager-ready
    t_ready

task occurrence admitted to executor
    t_submit

worker becomes physically available
    t_idle

task dispatched
    t_dispatch

task begins/executes
    t_run

task result reaches executor/manager
    t_complete
```

Candidate #102 changes `t_submit`, allowing it to precede `t_idle` for a bounded reserve.

The measurable opportunity is:

```text
max(0, t_dispatch - t_idle)
```

for redispatches, together with whether useful ready work existed during that interval.

The candidate must not confuse queue wait `t_dispatch - t_submit` with harmful worker idle. A reserve intentionally increases some queue wait while attempting to reduce worker idle.

## DP-17 — containment / ownership

Current ownership survives #102-A unchanged:

- canonical q node is contained by manager graph;
- task occurrence is contained by executor lifecycle once submitted;
- execution is contained by one worker at a time;
- private TT/residual state remains contained by that worker;
- liveness authority remains externally visible through the task's manager-owned `needed` word.

The only ownership extension is that manager may have more submitted-but-not-running task occurrences.

This requires no shared recursive table and no worker-side dependency mutation.

## DP-18 — multiplicity

Relevant cardinalities are distinct:

```text
R = manager-ready leaves
A = active workers
I = idle workers
Q = executor queued authoritative tasks
P = outstanding submitted tasks = A + Q (ordinary case)
W = configured workers
```

Current reserve-0 bound:

```text
P <= W
```

Candidate:

```text
P <= W + K
```

where `K = readyReserve`.

Multiplicity is useful only if `R` frequently exceeds the unsatisfied active capacity and task durations are uneven enough for completion order to matter.

Instrumentation now records ready samples, max ready leaves, queue maxima and idle-with-ready events.

## DP-19 — dual / reversed structure

Push and pull descriptions can be observationally equivalent at the resource boundary.

Current executor implementation is mechanically “push” from `pump()`, but semantically:

```text
worker becomes idle
+ queued eligible occurrence exists
-> worker receives next occurrence
```

This realizes the same next-available-resource relation that a worker-issued “claim” request would realize, without a second synchronization protocol.

Therefore “worker-driven acquisition” must be judged by the realized relation, not by which side calls `postMessage`.

A literal worker-side pull protocol is only warranted if it removes measured latency or contention left by `pump()`.

## DP-20 — complement / exclusion structure

A task occurrence at any instant is in exactly one scheduler lifecycle category:

```text
manager-ready but unsubmitted
queued
running
completed exact
completed split
retired
failed/aborted
```

Queued and running are mutually exclusive.

“Ready” and “needed” are not complements:
- a task can have been ready when submitted and become unneeded while queued/running;
- retirement represents this temporal exclusion exactly.

No scheduler may interpret `needed=0` as a game value.

## DP-21 — compositional structure

The exact scheduler result composes from:

```text
manager dependency semantics
+ task transport/replay contract
+ executor resource assignment
+ worker task semantics
+ result validation/publication
```

#102-A substitutes only the executor-admission schedule. Since each task descriptor and result contract remains identical, semantic qualification can be localized while end-to-end performance still requires whole-system measurement.

Future affinity can compose as an advisory ordering relation over the same eligible task set; it need not alter the task contract.

## DP-22 — alternative decomposition

Five decompositions were explicitly considered:

### A — reserve-0 central admission
Incumbent.

### B — bounded global reserve
#102-A. Existing executor queue, no new worker protocol.

### C — per-worker local queues + stealing
Potentially preserves affinity but introduces task placement before availability and steal synchronization. Not first-line because current tasks are not worker-bound.

### D — worker claim against manager-published IDs
Mechanically decentralized reservation. Requires a claim protocol, duplicate-claim exclusion and wakeup/shutdown semantics. Semantically redundant unless B leaves measurable manager/executor latency.

### E — two-tier eligible set
Global ready reservoir plus soft worker-affinity preference, with immediate fallback to any work. This is the strongest follow-on if B establishes spare-reservoir value but locality loss is measurable.

No decomposition is accepted from architectural elegance alone.

## DP-23 — quotient / partition structure

Scheduler occurrences can be partitioned by:
- exact manager q_r node;
- parent occurrence/lineage;
- support/rank;
- last producing worker;
- current needed state;
- priority tier.

Only exact manager q_r is semantic value-sharing identity.

Worker-affinity partitions are heuristic/locality partitions. They may be useful even when tasks are not identical and must never authorize value reuse.

No new semantic quotient is introduced.

## DP-24 — local versus global structure

Global:
- q dedup;
- dependency readiness;
- exact completion;
- retirement truth.

Local:
- worker TT;
- residual pool;
- task preparation;
- worker utilization and cache warmth.

Candidate #102 deliberately leaves semantic truth global while allowing resource allocation to respond locally to whichever worker becomes free.

This is the precise “manager owns truth, resources consume admitted work” split.

## DP-25 — boundary condition structure

Important boundaries:

### Empty ready set
Workers may legitimately idle; no scheduler defect.

### Ready count below capacity
Some workers idle naturally.

### Ready count above capacity
Reserve can decouple future dispatch from manager refresh.

### Root becomes exact while queued work exists
Queued/running work must be retired/discarded exactly.

### Worker fault
Manager/executor must fail closed; queue must not reclassify partial work as exact.

### Shutdown with queue non-empty
Current executor close requires drain; manager retirement/abort must own cleanup.

The bounded reserve increases the frequency of “root closes with queued work” and therefore zero-node retirement is a primary measurement.

## DP-26 — boundary movement

The experiment moves exactly one boundary:

```text
before:
    manager-ready -> submitted
    only when active outstanding < W

candidate:
    manager-ready -> submitted
    while outstanding < W + K
```

It does **not** move:
- q ownership to executor;
- liveness ownership to worker;
- worker-local cache identity to manager;
- completion propagation off the manager thread.

This is the minimum boundary movement that tests assignment flexibility.

## DP-27 — latent correspondence / hidden common cause

Three apparent scheduler symptoms can share one cause:

- worker briefly idle after finishing;
- manager repeatedly recomputes readiness between dispatch waves;
- task-duration imbalance creates straggler gaps.

Common cause candidate:

> no admitted replacement work exists at the instant a resource becomes free.

#102-A addresses this cause only when the replacement was already manager-ready. It cannot solve:
- hidden q inside worker recursion;
- lack of manager-ready parallelism;
- a single genuinely critical straggler;
- duplicate recursive work from late q visibility.

Those remain #78/#89/#94 territory.

## DP-28 — dimension / unit structure

Do not collapse:

- milliseconds of worker execution;
- milliseconds of worker redispatch idle;
- milliseconds of queue wait;
- recursive nodes;
- task count;
- queued task count;
- ready leaf count;
- bytes of RSS;
- manager CPU;
- cache hits/classes.

A lower redispatch-idle number is not itself a performance win if nodes, retirement transport, memory or wall time rise.

Current benchmark uses exact nodes and wall/result-ready time as primary economic controls and queue timing as explanation.

## DP-29 — ordering / partial order

Current executor supports a total numeric priority plus FIFO sequence, but the semantic requirement does not imply a total global order.

The minimum scheduler relation is:

```text
eligible = ready AND submitted AND needed-at-dispatch
```

Within eligible work, possible future preference hierarchy:

1. immediately warm continuation/affinity if it does not wait;
2. bounded leverage tier (#90);
3. FIFO/age tie break.

#102-A deliberately leaves all priority at incumbent default 0 to isolate admission timing.

Finding: total queue sort is implementation machinery, not semantic authority. A future tiered/partial ordering may be cheaper, but current queue size must first prove large enough to matter.

## DP-30 — reachability / connectivity

Manager `required()` computes the currently root-relevant live subgraph.

Every submitted leaf must have been reachable in that live traversal at submission.

After ancestor closure, that occurrence may leave the live subgraph. Existing retirement sets its `needed` word to zero. If it remains queued, task-entry control returns retired before recursive work.

Thus a bounded reserve cannot create a false semantic reachability edge; its risk is economic transport of an occurrence whose reachability expired after publication.

This makes queued-obsolescence directly measurable and falsifiable.

## Segment disposition

DP-16..30 strengthens the initial result:

- “next available worker” is already the executor’s resource rule once work is admitted;
- the real candidate is early bounded publication into that eligible queue;
- queue wait and worker idle are different temporal quantities;
- reserve depth competes with obsolescence and locality;
- classic work stealing remains unjustified unless this lower-complexity relation fails for a measured mechanism that stealing would actually remove.
