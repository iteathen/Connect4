## DP-31 — conservation / balance

Scheduler reordering must conserve manager dependency semantics:

```text
set of exact values legally publishable
root value
root preserving action policy
dependency closure
```

may not change with worker count, reserve depth, completion order or worker identity.

Execution quantities need not be conserved:
- aggregate recursive nodes;
- task count;
- cache hits;
- memory;
- completion order;
- retirement count.

Those non-conserved quantities are exactly where scheduler economics live.

## DP-32 — threshold / phase boundaries

Likely scheduler phases:

1. `ready <= active capacity` — reserve has no useful work to add.
2. `ready > active capacity` — bounded reserve can pre-admit replacements.
3. root-critical narrowing — many queued siblings may rapidly become obsolete.
4. split-heavy regime — manager receives frequent continuation structure, reducing need for reserve.
5. long-task/straggler regime — reserve may hide completion imbalance only for noncritical available work.
6. cache-warm continuation regime — affinity may dominate marginal dispatch latency.

No universal reserve depth follows from worker count. The first grid 0/+1/+W is an empirical phase probe, not a final policy.

## DP-33 — degenerate / special cases

### One worker
A reserve cannot increase simultaneous execution. It tests only whether pre-admission avoids manager refresh between sequential tasks. If +1 helps materially here, the mechanism is dispatch-turnaround rather than multicore load balancing.

### More workers than ready work
Idle workers are correct; no reserve can manufacture parallel dependencies.

### Root exact at manager frontier
No worker scheduling is needed.

### Immediate forced/narrow chain
Reserve may be irrelevant; #95 owns chain topology.

### Broad ready frontier
Best opportunity for reserve and future priority/affinity.

### All queued tasks retired
Correct but economically pathological; candidate must narrow.

## DP-34 — failure-mode correspondence

#102-A must preserve existing fail-closed behavior:

- invalid result poisons executor;
- worker error/exit poisons session;
- abort causes no exact unfinished publication;
- retirement carries no value;
- manager capacity failure stays explicit;
- task ID/job ID mismatch remains fatal;
- shutdown waits for/drains task lifecycle.

A deeper reserve increases outstanding failure surface but does not change the failure algebra.

Future worker-side shared claiming would add new failure states (claimed-but-owner-dead, wakeup races, ABA/slot reuse). Because #102-A tests the resource relation without those states, those costs must be justified by evidence before introduction.

## DP-35 — exception structure

No exception/control-flow simplification follows from decentralization.

Recursive `try/finally` apply/undo remains exact.
Precreated quantum/retirement sentinels remain worker-local control.
Executor poison remains a session-level exception boundary.

Queue cancellation can be optimized later, but must not convert a retired task into silent exact completion.

## DP-36 — representation redundancy

The original handoff suspected worker/core identity might be redundantly represented in work identity.

Current source shows the redundancy has already been removed semantically:
- task descriptor contains no target worker/core;
- manager node contains no owner worker;
- executor chooses an idle slot at dispatch.

Remaining potentially redundant coupling:
- outstanding admission cap exactly equals worker count.

That equality is policy, not semantic structure.

Candidate #102 parameterizes it as:

```text
outstandingLimit = workerCount + readyReserve
```

This is the only representation/policy redundancy changed in the first experiment.

## DP-37 — equivalent constraint closure

For an already-ready manager leaf `L`:

```text
submit L immediately into a bounded queue
```

and

```text
hold L in manager-ready state until a slot is free, then submit
```

have the same semantic closure if:
- `L` is rechecked through existing liveness before recursive work;
- any obsolete result is discarded/retired under current rules;
- completion publication remains manager-owned.

They differ only in scheduling time and resource/cache economics.

This exact closure is the correctness basis for #102-A.

## DP-38 — semantic identity candidate discovery

No new natural/domain identity question is required.

Explicitly:

- same q_r dependency does not make two task occurrences the same occurrence;
- same continuation lineage does not make two worker executions physically identical;
- a worker capable of executing a task is an admissibility relation, not SAME;
- same CPU core is irrelevant to game identity;
- same worker-cache affinity class is a scheduling relation.

Qualified NEI 0.4 is therefore not invoked to produce a scheduler answer.

No Bayes factor is introduced.

## DP-39 — QU extension

Measurement-sensitive QU now connects directly to instrumentation:

```text
QU-SCHED-02 redispatch idle
    <- executor redispatchIdleMs*

QU-SCHED-03 queued obsolescence
    <- zeroNodeRetiredTasks + retiredTaskNodes

QU-SCHED-06 reserve depth
    <- reserve grid wall/nodes/memory

ready multiplicity
    <- readySamples/readyLeavesTotal/maxReadyLeaves

queue pressure
    <- maxQueued + queueWaitMs*
```

Still unmeasured in the first pass:
- precise private-TT reuse by affinity lineage;
- OS/NUMA migration cost;
- per-task dynamic hardware counters.

Those remain QU; they are not assumed negligible.

## DP-40 — global whole-structure isomorphism

The scheduler need not mirror the semantic q DAG one-to-one.

A correct resource scheduler may hold:
- multiple task occurrences referring to dependencies;
- queued occurrences that later become obsolete;
- private cache materializations.

The required homomorphism is narrower:

```text
exact worker result
-> correct manager q dependency
-> exact dependency closure
```

Trying to make workers themselves own the global q DAG would conflate semantic authority and resource scheduling and is not implied by decentralization.

## DP-41 — literal-value coincidence

Reject:
- equal worker IDs across sessions as persistent affinity identity;
- equal task IDs/job IDs as q relation;
- equal priority numbers as equal structural leverage;
- equal node counts as equal future cost;
- equal WDL as equal q.

Reserve depth values 1,2,4 are experiment controls only, not structurally privileged constants.

## DP-42 — lexical / name similarity

“Work stealing,” “pull,” “claim,” “queue,” and “next available worker” are not accepted by label.

The current executor mechanically pushes messages but already implements next-idle-resource acquisition semantics.

Therefore the campaign evaluates causal properties:
- who owns readiness truth;
- when work becomes eligible to resource scheduler;
- whether resources idle while useful eligible work is withheld;
- locality/coordination cost.

It does not require an algorithm to carry the name “work stealing.”

## DP-43 — shared ontology / class-label hints

Manager node, task occurrence, worker slot, OS thread and core all participate in “work execution” but belong to different ontological layers.

Shared “worker” terminology must not collapse:
- JS Worker object;
- persistent worker isolate;
- executor slot;
- logical CPU;
- physical core.

The first experiment needs only persistent JS worker identity for metrics/cache locality. It intentionally avoids OS affinity claims.

## DP-44 — serialization / layout similarity

Portable legal replay arrays are execution reconstruction data.

Their identical serialization across workers establishes portability of the task input but not q identity or cache identity.

A future SharedArrayBuffer ready structure must not replace the replay with pool-local class IDs merely because integer layouts are smaller.

The current bounded reserve therefore reuses the already-qualified transport representation.

## DP-45 — raw identifier correspondence

No correctness conclusion may follow from:
- workerId;
- taskId;
- jobId;
- residual class ID;
- q hash/slot;
- queue index;
- CPU number.

WorkerId may be used for measured affinity/continuation provenance only.

## Full structural synthesis before timing disposition

DP-01..45 yields the following exact architecture statement:

```text
global dependency truth:
    remains centralized in Branch Manager

execution-resource assignment:
    already worker/core-flexible in the current executor

remaining coupling:
    manager admits at most W outstanding occurrences
    even when >W root-relevant leaves are ready

lowest-complexity decentralized-allocation experiment:
    admit W+K ready occurrences
    let existing executor hand queue head to next idle worker
    preserve task-entry retirement

possible follow-on:
    eligible reservoir
    + soft warm-affinity preference
    + immediate any-worker fallback
```

The protocol therefore falsifies the need for a **worker-ID-targeted redesign** and does not justify a SharedArrayBuffer work-stealing deque yet.

The economic disposition of #102-A remains pending the alternating fresh-process benchmark. Structural plausibility alone is insufficient.

## Promotion burden

Promote any scheduler change only if all hold:

1. exact value/root-action controls pass;
2. no completion/cancellation lifecycle regression;
3. wall/result-ready time improves or a clearly bounded regime-specific policy is identified;
4. aggregate work does not rise enough to erase time benefit;
5. queued-obsolescence/transport remains bounded;
6. memory remains acceptable;
7. repeat confirmation survives alternating fresh processes;
8. no stronger affinity/priority claim is smuggled into the isolated reserve experiment.

If #102-A fails, preserve the negative result and move only to a candidate whose mechanism addresses the observed failure mode.
