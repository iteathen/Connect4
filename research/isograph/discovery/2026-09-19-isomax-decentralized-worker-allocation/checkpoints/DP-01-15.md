## DP-01 — cross-boundary relational structure

PASS with correction to the original hypothesis.

Current execution already separates canonical q dependency from worker identity:

```text
manager canonical q_r node
    -> portable task occurrence (legal replay)
    -> executor queue
    -> any idle worker slot
```

There is no persistent `q -> predetermined worker/core` edge in current source.

The remaining boundary mismatch is:

```text
manager ready set can contain additional useful leaves
    but
manager admits at most workerCount outstanding tasks
    therefore
executor can have an idle worker with no already-admitted reserve task
```

This is an admission/refresh coupling, not semantic worker ownership.

## DP-02 — constraint structure

Exact constraints retained by every scheduler candidate:

- manager alone owns canonical q/dependency truth;
- unfinished/split/retired work is not W/D/L;
- exact completion may publish only `{-1,0,+1}`;
- task payload uses accepted legal replay, not pool-local residual IDs;
- `needed` remains manager-owned liveness authority;
- worker private TT/residual state may survive task boundaries but does not become global identity;
- root action selection remains center-first and completion-order independent;
- first-win stopping and q_o/q_r distinction remain unchanged.

These constraints do not require a worker assignment chosen before execution.

## DP-03 — interface / ownership

The current minimum authority split is:

```text
Branch Manager:
    canonical q_r nodes
    dependency graph
    readiness
    liveness / retirement
    exact completion propagation
    root witness semantics

Executor:
    eligible admitted occurrence queue
    priority ordering
    idle/busy resource accounting
    worker fault ownership

Worker:
    private IsoMaxTaskSolver
    private residual pool / TT
    task-local recursion
    exact/split/retired result

CPU core:
    outside semantic model
```

Finding: task selection from the *manager-ready universe* remains manager-owned; worker selection is already executor/resource-owned. Candidate #102 moves only the **admission timing** boundary by publishing a bounded reserve.

A worker-side global dependency scan is rejected: it would duplicate manager truth ownership.

## DP-04 — dependency topology / reachability

Any manager leaf returned by `required()` is a reachable unresolved root dependency occurrence. It is therefore semantically admissible for any healthy worker that can reconstruct its replay.

A queued occurrence can later become unreachable because an ancestor closes. This is already represented exactly by its `needed` word.

Thus:

```text
ready at publication
    does not imply
still needed at execution
```

The candidate may queue ahead only because task-entry retirement safely distinguishes those cases.

A future queue-pruning optimization is an execution optimization, not required for correctness.

## DP-05 — QU structure

Scheduler uncertainty is retained as separate dimensions:

### QU-SCHED-01 — future ready-work persistence
How often a currently ready leaf remains needed long enough to execute.

### QU-SCHED-02 — redispatch idle interval
Time from worker completion to next authoritative dispatch when useful work exists or can already be admitted.

### QU-SCHED-03 — queued obsolescence
Frequency/cost of tasks becoming unneeded before or immediately after dispatch.

### QU-SCHED-04 — private-cache affinity value
Saved TT/residual work when a related occurrence runs on a warm worker.

### QU-SCHED-05 — queue coordination cost
Structured-clone, ordering, queue operations and any future Atomics cost.

### QU-SCHED-06 — admission depth
Best reserve depth under worker count and workload shape.

### QU-SCHED-07 — future task duration
Straggler tail is unresolved at admission; node budget is only a bound/proxy.

No scalar scheduler score is assumed.

## DP-06 — repeated motifs

Repeated lifecycle motif:

```text
manager discovers leaf
-> admit
-> queue/dispatch
-> worker exact|split|retired
-> manager updates dependency truth
-> new leaves become ready
```

Current reserve-0 execution serializes the *admission refresh* portion of this motif behind each completion event even though executor dispatch itself is generic.

Repeated cache motif:

```text
worker completes task
-> retains private pool/TT
-> next task may or may not be structurally related
```

This establishes the later competition between availability and affinity but does not select affinity.

## DP-07 — alternative factorizations

Compared factorizations:

A. **central push / reserve 0** — current default.

B. **bounded shared pull semantics via existing executor queue** — manager publishes >active-slot ready occurrences; next free worker consumes queue head. This is #102-A and is the first experiment.

C. **worker-side shared Atomics queue** — not yet justified. It changes coordination mechanism but not the semantic admission set.

D. **manager authority + atomic reservation of q IDs** — unnecessary for current single manager thread unless admission itself moves off-thread.

E. **hybrid soft-affinity pull** — eligible set plus worker preference; candidate only after availability economics are measured.

Finding: B is the smallest factorization that tests the user’s desired “next available worker” property because the executor already realizes that property once work is queued.

## DP-08 — residual structure after partial correspondence

Two occurrences that can compute the same final q value are not thereby the same occurrence.

After exact q_r correspondence, residual distinctions may remain:

- parent/action provenance;
- task ID;
- continuation lineage;
- worker cache warmth;
- queue age;
- retirement state.

These residuals are scheduler facts. No NEI SAME claim is required.

## DP-09 — automorphism / symmetry

Horizontal reflection remains the only qualified game automorphism relevant here.

Worker permutation is **not** a game semantic automorphism claim. It is execution-resource substitutability under the task prerequisite contract.

CPU-core permutation likewise carries no semantic identity consequence.

No scheduler candidate may infer literal move-label identity from q_r.

## DP-10 — role-equivalent elements under different labels

`workerId`, executor slot index, OS thread, and physical/logical core are not interchangeable stored identities even though all may name an execution resource at different layers.

The current task result reports `workerId` for provenance/measurement. That does not make worker ID part of task or q identity.

`jobId` is manager occurrence identity; executor `taskId` is transport lifecycle identity. They must remain distinct.

## DP-11 — invariants across admissible worker variation

For any healthy worker admitted to execute one portable task descriptor:

```text
same legal replay + same ordinary profile
    -> exact task semantics independent of workerId
```

subject to exact result/split/retirement lifecycle.

Private cache contents may change cost and split point under a node budget, but may not change the exact W/D/L eventually published.

This is an execution-substitutability invariant, not natural identity.

## DP-12 — known/unknown interfaces

Known:
- executor can queue authoritative work;
- executor dispatches to next idle slot;
- workers reconstruct from portable replay;
- queued obsolete tasks can retire at entry with zero nodes;
- manager can cancel already-running work through `needed`.

Unknown:
- queue reserve economics;
- queue-age versus obsolescence;
- exact cache-locality value per worker;
- whether worker-side claiming would remove any additional measurable latency.

These unknowns remain QU, not semantic UNKNOWN values.

## DP-13 — multi-scale structure

Allocation exists at distinct scales:

```text
recursive node       worker-local
task occurrence      portable execution unit
ready set            manager-local dependency view
executor queue       process-local resource scheduling
OS thread/core       runtime/physical placement
```

The candidate deliberately moves only one boundary: ready-set occurrence -> executor queue earlier.

A global recursive work-stealing scheduler would cross several additional scales and is therefore not the first experiment.

## DP-14 — transformation invariance

Changing:

```text
reserve depth 0 -> reserve depth k
```

does not transform game state, q, value algebra, task payload, or task quantum.

It transforms only the time at which an already-ready execution occurrence is admitted to the executor.

Correctness therefore reduces to:
- exact liveness at execution;
- no duplicate completion corruption;
- unchanged manager dependency propagation;
- unchanged worker result validation.

The added adversarial tests qualify these properties for the bounded implementation.

## DP-15 — information flow

Current reserve-0 flow:

```text
manager knows ready leaves
-> admits only active-slot count
-> executor drains admitted set
-> completion Promise resolves
-> manager recomputes required()
-> admits replacement
```

Potential information delay:

```text
manager-ready leaf exists
but executor has not been told about it
```

#102-A moves only that information boundary:

```text
manager publishes bounded reserve
-> executor already knows eligible replacement
-> worker completion invokes pump()
-> immediate next dispatch
```

The experiment must distinguish:
- true idle removed by early publication;
- queue wait deliberately introduced by reserve;
- stale queued work later retired.

## Segment disposition

The original “fixed worker/core assignment” hypothesis is falsified by current source.

The surviving exact candidate is narrower and stronger:

> Preserve global dependency authority in Branch Manager, but decouple ready-work admission from the exact number of currently active workers so the existing next-idle-worker executor can consume a bounded reserve.

No NEI result is needed. QU owns the economics. #102-A is currently under measurement.
