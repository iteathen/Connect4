## DP-19 — Dual / reversed structures

PASS; reject false own/block duality.

Mover and blocker residual transitions operate on the same residual vocabulary but are not interchangeable:

```text
own:
    cofactor + reduction + antichain normalization + possible terminal

block:
    deletion of terms containing landing cell
```

The shared vocabulary does not justify a single generalized kernel. The previous lazy/branchy own mover was already rejected on real economics, while #100 correctly keeps own dense and treats blocker locality separately.

The only new exact asymmetry is F-002: after frontier exact closure, the scoped worker mover is nonterminal. This removes one capability from the mover kernel without making it equivalent to blocker deletion.

## DP-20 — Complement / exclusion structure

PASS with a new provenance-scoped lead.

Native frontier consequence classes are mutually exclusive under own-win precedence:

```text
exact
forced
quiet
```

For a native forced result, the cell is obtained from:

```text
opponent singleton masks
    AND maintained playable masks
    -> exactly one playable cell
```

The ordinary solver nevertheless routes that cell through `columnForForcedCell()`, which revalidates:
- integer/range;
- column/row decomposition;
- `canPlay`;
- height equality.

Those checks are necessary for externally supplied/certificate forced cells, but native and certificate consequences currently merge into one `forcedCell` variable.

**F-005 — preserve forced-cell provenance long enough to avoid proof-facing validation for native-only worker consequences.**

This is exact precondition transfer, not global validation removal.

Issue search found no dedicated candidate. Conceptually it belongs with the trusted-boundary work previously screened under #86 and optional proof/native ABI separation in #87. Because #86's tested fast paths did not include this exact forced-cell provenance seam, the result is not already falsified; because #86 found general validation removal neutral, F-005 remains lower priority until forced-transition frequency/cost is measured.

## DP-22 — Compositional-structure discovery

PASS with a stronger manager-side factorization lead.

Current Branch Manager expansion does:

```text
expand(node):
    replay node.moves -> parent state

for each legal child:
    construct [...node.moves, column]
    build(childMoves):
        replay the entire child history from empty
        derive q
        lookup/create canonical node
```

Thus one already-materialized parent transition is discarded and reconstructed from history for every child.

The exact state operation is compositional:

```text
parent native state
    + applyUnchecked(column)
    -> exact child native state
    -> q_r lookup
    -> undo
```

No new semantic representation is required.

**F-006 — manager child q construction from the already-live parent state rather than full child replay.**

Candidate shape:
1. replay the parent once, as today;
2. for each admitted child column, `applyUnchecked(column)`;
3. use the resulting exact child state directly for manager q lookup/create;
4. retain/copy the legal move path only as transport/provenance required by current task API;
5. undo before the next sibling.

This avoids repeated child replay while preserving q equality and the existing representative-occurrence model.

## DP-23 — Reconstruction-structure discovery

PASS; F-006 is specifically reconstruction excess.

The current factorization reconstructs child semantic state from full move history even though the complete parent semantic/runtime state is already present one edge away.

The move path remains necessary for portable worker task transport because pool-local class IDs cannot cross pool identity domains. That does **not** imply the manager must replay the same path merely to compute a child q.

Correct boundary:

```text
manager local derivation:
    parent state + one move

worker transport:
    legal move replay
```

These are different consumers and need not share the same reconstruction method.

Issue #85 already owns manager dependency-graph/transport churn and explicitly listed replay-prefix structure as a candidate family. Its tested epoch-mark replacement was rejected, but this one-edge reuse was not the tested candidate. Per issue policy, F-006 should strengthen #85 rather than create duplicate issue noise unless measurement establishes a separate owner.

## DP-24 — Proof / witness topology

PASS; no proof identity leaked into q.

A scalar exact value does not carry a root action witness automatically.

Serial `solve()` reconstructs a deterministic value-preserving action after exact value resolution; manager execution separately preserves center-first root witness semantics.

Storing proof/witness identity in q or WDL cache would broaden the semantic payload and is not justified. The bounded root-witness reconstruction is outside the high-frequency recursive recurrence.

No new candidate promoted here.

## DP-25 — Refinement-relation discovery

PASS with provenance refinement.

The hot path contains several refinement relations:

```text
hash locator
    < exact q_r coordinates

q_r
    < q_o + orientation for literal-label reconstruction

native forced consequence
    < generic forced consequence with external-proof validation burden

quiet/forced frontier state
    < generic state admitted to terminal-capable mover cofactor
```

F-002 and F-005 both arise because a stronger upstream refinement is erased before a downstream generic interface.

This is not NEI: the represented referent is unchanged; only exact known preconditions are being preserved.

## DP-26 — Boundary-movement invariance

PASS with four distinct boundary-placement candidates/owners.

1. **#98:** terminal classification before q lookup / first-win dead-state suppression.
2. **F-002 -> #100-family:** move the frontier's nonterminal-mover fact into a worker-scoped own-cofactor specialization.
3. **F-005 -> #86/#87-family:** retain native forced provenance past classification so proof-facing validation is not mandatory for native-only workers.
4. **F-006 -> #85-family:** derive child q at the live parent-state boundary; keep move replay only at the cross-worker portability boundary.

A boundary move is valid only where its exact precondition remains available. None authorizes weakening public APIs.

## DP-27 — Parameter-role correspondence

PASS; no accidental parameter conflation found.

Important parameter roles remain separate:

- `taskNodes`: scheduling quantum;
- residual/cache reservations: capacity derived from quantum but not identical policy;
- 512 nodes: necessity/abort polling cadence;
- transition-prefix 64K: residual transition memo boundary;
- executor `priority`: currently unused IsoMax scheduling channel (#90);
- cache hash: locator;
- q coordinates: equality;
- q orientation/transporter: literal-action reconstruction only.

Prior experiments already show these parameters cannot be tuned as one scalar:
- 32K task quanta lost;
- 128K helps one/two workers and loses at four;
- extra TT reservation was rejected;
- 512 polling was retained independently.

#94 remains the correct owner for structural/adaptive parameter policy.
