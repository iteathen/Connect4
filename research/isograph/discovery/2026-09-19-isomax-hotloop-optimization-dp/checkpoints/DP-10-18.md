## DP-15 — Information-flow structure

PASS with two findings.

### A. Frontier fact is not consumed by the residual kernel

Current information flow is:

```text
nativeFrontierCode
    proves no immediate mover win
        |
        v
solver chooses forced/quiet edge
        |
        v
general ownTransition
    rechecks singleton terminality
    retains per-reduction terminal branch
```

The proof fact dies at the solver/residual interface. F-002 is therefore specifically an **information-flow failure / lost precondition**, not just duplicated syntax.

### B. Exact worker knowledge is only partially exported

A worker may complete many exact internal q values. At exact task completion only the task-root WDL is published to Branch Manager; internal exact q remains private/warm in that worker. On split, selected continuation child values are exported.

This is existing #78 ownership and reinforces F-001. It does not justify recursive shared-TT coordination.

## DP-17 — Containment / ownership structure

PASS with one new measurement-gated runtime lead.

### Generic q cache ownership

The generic transition cache is intentionally used for both:
- arbitrary manager node/object payloads;
- ordinary recursive WDL.

Therefore #101 remains the correct ownership-clean specialization candidate. Global narrowing of `values` is rejected.

### Per-task memory observation lies on worker turnaround

Every successful worker task currently does:

```js
parentPort.postMessage({
    ...,
    isolateMemory: process.memoryUsage()
})
```

after `runTask` and before the result reaches the manager.

Node 26 documentation states that `process.memoryUsage()` iterates over each page to gather memory data and “might be slow depending on the program memory allocations”; only `memoryUsage.rss()` is explicitly documented as the faster RSS-only call.

Source:
https://nodejs.org/api/process.html#processmemoryusage

This matters structurally because prior real execution evidence has thousands of task completions, while `executionMs` is measured around `runTask` and therefore excludes this post-run observation cost.

**F-004 — per-task full-memory census on result critical path**

## DP-18 — Cardinality / multiplicity structure

- many q occurrences per canonical manager q;

Record as **stopped low-information route** until allocation evidence isolates task-state construction.
