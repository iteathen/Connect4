No convenient realization is silently selected.

### Minimality is not overclaimed

The very first open dimension is minimality/canonical presentation.

Therefore the current RBA graph does **not** claim:

```text
current representation = minimum sufficient support
or
current representation = canonical minimum-cost realization
```

DP 0.8 adds no reason to manufacture either claim.

### Execution placement is not semantic structure

Topology placement 0.8 explicitly states that selected rank26 support is execution state, not a native relation.

That already satisfies the required separation between:

```text
represented structural law
and
current execution placement / work frontier
```

### No valuation profile is supplied

The current artifacts contain exact evaluations and selected performance observations, but no complete application valuation profile for choosing among alternative sufficient RBA realizations.

Therefore no transition-count, node-count, wall-time, cycle, or memory preference is inferred merely from availability.

## DP 0.8 follow-up rule

A future RBA sufficiency/valuation view should be created only after a concrete target is declared, for example:

```text
target:
    exact rank26 draw16 closure

candidate space:
    named exact evaluation/topology alternatives

preserved obligations:
    realizability
    deadline/resource/first-win guards
    exact value semantics

valuation:
    supplied separately
```

Until such a target/profile exists, the correct modernization action is to preserve the current native research state.
