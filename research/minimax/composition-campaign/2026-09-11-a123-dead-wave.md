# U1 A1-A3 certificate + DEAD composition wave

**Date:** 2026-09-11  
**Status:** research evidence only; no maintained solver promotion.

## Governing boundary

This wave preserves two different exact abstractions rather than conflating them:

- DEAD owns exact neutral/dead physical-choice compression using a finite pooled tempo state;
- A1-A3 strategic certificates are evaluated against the actual physical support surface.

When DEAD has retired a column into the neutral pool, the certificate check temporarily restores the retired height, performs the strategic proof on physical support, then returns to the pooled DEAD identity before ordinary search continues.

This avoids assuming that an Allis response strategy remains valid merely because two physical support states are game-value equivalent under DEAD.

## U1 role-generalization of A1/A3

The future-event rank identity

`N(t) = (W-1)H - ply + row(t) + 1`

was used to generalize Claimeven/Vertical by player role rather than fixed board-square parity.

At a state:

- the response controller is the player **not** to move;
- for an adjacent empty pair, if U1 assigns the upper event to that controller, the pair supplies the Claimeven-style singleton blocker at the upper square;
- otherwise the pair supplies the Vertical-style two-cell blocker;
- Baseinverse remains the split blocker over two directly playable cells.

On ordinary even-ply states this reproduces the historical Allis even/odd split. On odd-ply states it flips automatically with the current controller.

## Current elapsed-time boundary

The best proof-work stack is not yet the fastest implementation because dynamic A123 dominates CPU cost.

In the strongest event-SEWB + DEAD context:

- no A123: 1,119 nodes, ~3.034 ms median in this shared-runner batch;
- A123 before: 823 nodes, ~3.580 ms;
- A123 after: 825 nodes, ~3.320 ms.

Therefore the immediate engineering target is **not** to discard A123. It is to eliminate dynamic certificate construction/selection cost using the already-proposed U1/U2 architecture:

`SUP/event + U1 parity/response descriptors -> certified blocker IDs -> U2 625-ID closure`.

## Updated execution order for current forms

For the present dynamic certificate form, the preferred performance order is:

`RWS/RID/SUP -> IWIN -> DTH -> FBLK -> FMAC -> DEAD identity normalization -> event-SEWB -> A123 on restored physical support -> AUTO(pre-score) -> E1 -> E2 -> neutral tempo absolute-last`.

A123-before-SEWB remains a valid reverse-order control and can regain priority if the certificate becomes materially cheaper/incremental.
