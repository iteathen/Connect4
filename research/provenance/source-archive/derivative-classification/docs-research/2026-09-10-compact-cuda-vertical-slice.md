## Assessment and execution contract

Proceed with an experimental compact physical profile. Reuse the qualified
ownership recurrence, not the dense colored-state representation. B1's reported
35.35 billion subset checks/s motivates this experiment but predicts neither
full-solver throughput nor frontier growth. The packed42 CPU 5x5 reference
reports 81,515,570 pair candidates and about 18.86 s; 6x5 and 7x6 exceeded 600 s.

The strongest objection is orchestration: a GPU pair helper called from the
CPU support loop would leave semantic progression on the host. Instead, freeze
the finite support/rank schedule before execution; device blocks own cofactor,
terminal override/subtraction, pair generation, normalization and rank results.
Two rank arenas retain authoritative output; reusable per-shard scratch bounds
candidate residency. Host submissions follow only the static schedule.

Terminal subtraction has an exact intersection form: subtracting the upward
set generated by requirement q from a downward frontier intersects it with the
maximal caps U\\{x}, x in q. The dual intersects an upward frontier with singleton
generators {x}, x in U\\forbiddenCap. Each sequential line subtraction therefore
uses the same exact packed pair algebra. No search or physical-state enumeration
enters execution. The existing CPU solvers remain qualification oracles only.

Capacity overflow invalidates the solve; it never truncates a valid result.
Blocks stop uniformly at collective boundaries. CUDA operation completion is
separate from successful root closure. Counters must fail closed on overflow.
Output ordering within equal cardinality may vary; exact set equality is the
qualification criterion. Oracle comparisons cannot feed semantic progression.
