# IsoMax native WSL integration — 2026-09-16

**Direction / structural architecture:** Josh Oshiro  
**Formalization / implementation / qualification:** OpenAI ChatGPT  
**Branch:** `isometric`

## Question

Can corrected WSL semantics be made native to IsoMax without turning every support, turn, timing, resource and realizability distinction into one universal identity and thereby destroying structural reuse?

## Implemented answer

Yes, for the currently implemented standard-7x6 semantics. The active implementation separates three authorities:

```text
coarse canonical WSL signature  -> retrieval / structural grouping
claim-specific typed guard      -> proof/certificate transfer authority
support-aware transition key    -> exact behavioral memoization authority
```

Proof identity is independent of the transition key.

The implementation is in `components/isometric/` and does not carry a compatibility copy of the incumbent board/search state.

## Native representation

The standard board compiles to the exact 625 non-empty residual-requirement vocabulary generated by the 69 geometric Connect-4 lines.

Runtime residual classes use:

```text
625 ontology bits
= 20 x u32
= 10 x two-word storage slots
```

Each player owns one interned minimal residual-antichain class. Support/accessibility is carried separately by 42-bit masks plus a 27-bit support code (`7 x 3-bit heights + 6-bit rank`).

Transitions use the previously qualified target-scale forms:

- dense mover cofactor transform with minimal-antichain reduction;
- direct slot-local opponent blocker deletion;
- first-win terminal sentinel;
- bilateral residual exhaustion as draw certificate.

The previously tested branchy lazy-mover transform was not restored.

## IsoMax identity separation

`IsometricState.structuralSignature()` canonicalizes only the two residual classes under horizontal reflection. It is intentionally a coarse retrieval signature.

`IsometricState.transitionSignature()` strengthens that identity with canonical packed support, side to move and terminal status. It is the current exact memoization identity for native recursive W/D/L.

`IsoMaxCertificateIndex` indexes guarded proof/certificate records under the coarse signature. A proof transfers only when its typed guard is applicable through a valid canonical transporter. Horizontal stabilizer ambiguity is handled by considering both transporter images rather than allowing an arbitrary canonicalization choice to decide proof validity.

The current cheap guard set covers support/playability masks, side to move, rank and conjunction. Temporal, resource and realizability guard kinds are represented explicitly but return `UNRESOLVED` until their exact semantics exist.

## Native exact consumer

`IsoMaxSolver` now consumes `IsometricState` directly.

Authority order:

```text
transition memo
-> native WSL exact/forced frontier consequence
-> guarded IsoMax certificate
-> exact forced transition where certified
-> exact P0-oriented max/min W/D/L over unresolved residue
```

There is no heuristic evaluator fallback and no incumbent-state adapter.

## Qualification

### Residual-state differential

An independent physical-board reconstruction from the 69 winning lines was compared against both packed residual antichains at every nonterminal prefix over 96 deterministic games. The packed classes matched exactly.

Additional controls cover:

- all 625 term reflections are involutive;
- play/undo restores exact native state;
- first-win stopping;
- mirrored structural and transition signatures;
- guard applicable/inapplicable/unresolved semantics.

### IsoMax transfer controls

Qualified controls cover:

- guarded proof transfer across horizontal reflection;
- proof-identity deduplication independent from transition identity;
- mirror-shared support-aware transition memoization;
- immediate-win, unique-forced-reply and double-threat exact native frontier consequences.

### Independent exact solver differential

The native exact residue solver was compared with a separate physical-board minimax oracle on late legal roots and their mirrors. W/D/L agreed and selected moves preserved the independently computed exact root value.

A test fixture initially assumed that prefixes of one 42-ply cooperative draw were themselves game-theoretic draws. The physical oracle disproved that assumption: the relevant prefix was a forced P1 win. The native IsoMax solver agreed with the oracle. The certificate test was corrected to a separately established late draw fixture with live residual space for both players.

This is useful falsification evidence: the independent oracle caught a bad test premise rather than the implementation being changed to satisfy it.

## Current performance question

Correctness is no longer the immediate unknown for the implemented slice. The next IsoMax-specific question is the cost of the corrected semantics.

Measure separately:

```text
per-transition native WSL cost
coarse structural-signature cost
support-aware transition-signature cost
cheap typed-guard cost
guarded certificate lookup cost
coarse WSL class count
support-aware transition class count
class-split distribution
horizontal-reflection reuse
proof/certificate reuse where available
```

The principal risk remains quotient fragmentation rather than raw mask operations. The benchmark must therefore report both time and class counts; a fast guard check does not compensate for accidentally destroying useful quotient reuse.

Those are separate questions.
